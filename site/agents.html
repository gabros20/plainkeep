for AI agents

Your AI can run it too. With exactly your permissions.

Point any capable agent — Claude Code, Codex, anything that can read a file and run a command — at your vault, and it drives the same system through the same door. It reads a written contract, gets machine-precise answers, and hits the same safety rules you do. An assistant is a guest here, never a superuser.

Everything an agent needs is written down.

Three artifacts make the system drivable without guessing. AGENTS.md is the operating contract — what an agent may do and how. plainkeep.json is the generated manifest of every command: its arguments, its risk class, its exact subcommand grammar. And every command answers in JSON with one fixed shape when asked with --json, plus a five-value exit-code protocol. No prose-parsing, no screen-scraping, no vendor SDK.

plainkeep.json — one command, trimmed
{"verb":"task", "risk":"safe_write", "dry_run":true,
 "actions":[
   {"name":"add",  "args":[{"name":"title","required":true}]},
   {"name":"move", "args":[
     {"name":"id","complete":"task-id"},
     {"name":"status","enum":["inbox","active","waiting","done"]}]},
   {"name":"done", "args":[{"name":"id","complete":"task-id"}]}]}
one frozen answer shape
$ plainkeep task add "Fix the Acme webhook" --json
{"plainkeep_json":1,"ok":true,"verb":"task",
 "data":{"id":"T-20260816-01","status":"active"}}

# exit codes are the protocol:
# 0 ok · 2 usage · 3 needs --yes · 4 not found · 5 denied

Refusals teach. Completion knows your content.

A refused call is not a dead end — the error carries the exact corrected command, so the agent's next call is right. And the same completion brain your shell uses is queryable: candidate values for any argument, pulled live from your actual notes and tasks. An agent never has to invent a slug and hope.

the refusal carries the fix
$ plainkeep backup run --json
{"plainkeep_json":1,"ok":false,"error":{"code":3,
 "message":"restic backup of the working set needs --yes",
 "hint":"re-run: plainkeep backup run --yes"}}

# exit 3 — the agent reports to the human and waits.
# it never pre-appends --yes on its own.
ask before guessing
$ plainkeep complete --json task done
[{"value":"T-20260816-01","description":"Fix the Acme webhook"},

plainkeep mcp

MCP, generated — not hand-maintained.

For agent hosts that speak MCP, plainkeep mcp is a stateless server whose tool list is generated from the same command manifest — every built-in and every plugin, with schemas and hints, always current. Each tool call shells back through the ordinary command, so the safety rules and the logs stay the single enforcement path. Spawned per session, dies with it; no daemon lingers.

hook up an MCP host
$ plainkeep mcp --setup
claude mcp add plainkeep -- /Users/you/.local/bin/plainkeep mcp

# tools generated from plainkeep.json — every verb,
# every installed plugin. each call re-enters
# `plainkeep <verb> --json`: guardrail intact.

The rules agents live by.

The contract isn't just an API reference — it's an operating discipline. The load-bearing rules, in plain words:

1Never invent a command. The manifest is the complete list of what an agent may do. Something missing? It proposes; it doesn't improvise.
2Never compose paths by hand. The agent supplies content and judgment; the command computes where things go. No freelance file-writing.
3Orient before acting. Read the journal, check status — so two sessions never contradict each other.
4Log what you did. One journal line per meaningful action. An action nobody can see didn't happen for the next session.
5Drafts, not truth. AI-written notes stay marked draft until the human promotes them.
6Never transmit. No emails, no posts, no payments, no deploys. Drafts only; the human sends.
7Ask-first actions stay with you. Anything confirm-class — including turning schedules on or off — happens only on your explicit request.

Verified, not hoped.

The contract was put through an 18-scenario simulation run independently by two different operator models. Both finished 18 of 18 with zero divergences — same filing decisions, same refusals, same traversal of the vault. When two different AIs read the same rules and behave identically, the rules are unambiguous.

There's also llms.txt — a routed map of the docs for any model that lands here — and the full normative spec in the machine contract.
