plainkeep job

Your day runs itself.

This is the premise of the whole system: your day should open and close whether or not you remember to type. When you install, the setup wizard offers a schedule — on by default — and asks one human question: when does your day start, and when does it close? From then on, the morning journal opens itself and the evening digest writes itself.

jobwhen (yours to change)what it does
startdaily 07:30opens today's journal, carries unfinished tasks forward
close_nudgedaily 18:30writes the day's digest, flags loose ends for tomorrow
indexevery 60 minkeeps search current
consolidatedaily 02:30the nightly tidy-up digest
organize_scanweekly Sun 03:00proposes filing improvements — proposes, never applies
backup_checkweekly Fri 17:00nags if your backup is getting stale
change any time — no ceremony
$ plainkeep job set close_nudge --daily 22:00
set 'close_nudge' -> daily 22:00  (was daily 18:30)
  wrote jobs/registry.json

⚠ the schedule still runs the OLD time for 'close_nudge'
  make it live:  plainkeep job enable close_nudge --yes
always know what's live
$ plainkeep job status
6 job(s) — rendered / installed / loaded:

  start          yes  yes  yes  loaded
  close_nudge    yes  yes  yes  loaded
  index          yes  yes  -    installed, not loaded
  consolidate    yes  -    -    rendered only
rendered

The schedule is written down in your vault. Changing a time (job set) is a free, ordinary file edit — no permission needed.

installed

A copy has been handed to your Mac's scheduler. Turning that on (job enable --yes) asks you first, because it writes outside your vault.

loaded

The scheduler is actually running it. All three are reported separately, so a schedule can never quietly fail to exist — mismatches show up as "drift" with the one command that fixes it.

  • Only harmless job types can be scheduled — anything that would need your yes can never run unattended.
  • Nothing is lost by declining: every job is a normal command you can run by hand (plainkeep job run start).
  • One command turns it all off: plainkeep job disable --all --yes. (Scheduling is macOS for now; on Linux the jobs stay runnable by hand or from any scheduler you already use.)
plainkeep capture · triage

A thought lands in seconds. Filing comes later.

Capture takes whatever's in your head and drops it in the inbox — zero decisions, zero friction, so you actually do it. Later, triage walks the inbox with you and proposes a home for each item: a wiki note? a task? skip it? You approve; it files. The system never decides where your thoughts belong — it just makes deciding cheap.

capture now, decide later
$ plainkeep capture "ask Anna about the licensing deadline"
✓ saved to inbox/

# …later that day…
$ plainkeep triage
1 of 2 · "ask Anna about the licensing deadline"
  proposes: a task — sounds like something to do, not something to know
  [y] file it   [n] other   [s] skip
plainkeep task

A to-do list that's just folders.

Each task is one text file, and the folder it sits in is its status: inbox, active, waiting, done. Finish something and the file moves — no app state, no sync, nothing to corrupt. You can manage tasks entirely by command, entirely by menu, or by literally dragging files around; all three are the same thing.

  • task add "…" · task list · task done T-…
  • Open tasks carry forward into each morning's journal automatically.
tasks
$ plainkeep task list
active
  T-20260816-01  Fix the Acme webhook
  T-20260814-02  Draft the workshop outline
waiting
  T-20260812-04  Invoice approval — client side

$ plainkeep task done T-20260816-01
✓ moved to tasks/done/
plainkeep wiki

Notes that know each other.

Durable knowledge goes in the wiki: one idea per note, connected with [[links]]. Bigger things — a client, a project — get a hub note: a short, current summary that links out to everything about that thing. Ask a note who links to it, find notes going stale, find orphans nothing points to. It's a knowledge graph, but every node is a file you can read in anything.

  • wiki new · wiki open · wiki backlinks · wiki stale · wiki orphans
  • Works beautifully with Obsidian as a free viewer/editor — plainkeep doesn't care what you open the files with.
the graph, queried
$ plainkeep wiki backlinks acme-webhook
linked from:
  wiki/clients/acme.md          the client hub
  wiki/projects/acme-portal.md  the project hub
  journal/2026/08/2026-08-14.md

$ plainkeep wiki stale
untouched 90+ days:
  wiki/notes/pricing-model-v2.md
plainkeep search · index

Find anything you've ever kept.

Search runs entirely on your machine, in stages. Keyword search works out of the box and returns ranked hits pointing at the exact heading, with a snippet. Want "find it by meaning, not wording"? Switch on the optional semantic stage — local embeddings, no cloud — and the same command understands what you meant.

  • The index is a disposable cache: rm -rf .index && plainkeep index rebuilds it from your text. Your files are always the truth.
  • An optional enrichment step gives imported documents useful descriptions and keywords — using a small local model, degrading gracefully without one.
ask in your own words
$ plainkeep search "how do I stop a runaway agent"
1. wiki/notes/agent-guardrails.md#kill-switch
   …deny-class calls refuse before they run…
2. wiki/notes/plainkeep-rules.md#hard-rules
   …never transmits without a human…

# local keyword + link graph by default;
# semantic + reranking are one opt-in away
plainkeep files

PDFs, recordings, screenshots — in. Searchable notes — out.

Heavy files get filed into ~/files with a small text "shadow note" in your vault, so search can find them. Then, step by step and always on your machine: extract turns a PDF into readable text, audio into a transcript, an image into OCR'd words; distill drafts concept notes from the extract; organize proposes filing and linking improvements — each with its exact diff, applied only after you approve.

the pipeline
$ plainkeep files ingest talk.pdf --research --extract  # file it + make it readable text
$ plainkeep files distill talk                          # draft concept notes from it
$ plainkeep organize                                    # scan for links/dupes → proposals only
$ plainkeep organize review                             # page through each diff yourself
$ plainkeep organize apply --yes                        # apply ONLY what you approved
you wrote it

Your own notes. The default author, and what search trusts most.

a machine extracted it

Transcripts and extractions — always labeled with the source file and the tool that made them.

an AI drafted it

Model-written notes stay marked draft until you promote them. Machine text can never quietly become your truth.

plainkeep bookmark

Save the article, not just the link.

A saved URL becomes a real note: the readable text is pulled in, so it's searchable next year even if the page changes or dies. Add --archive and the full page is snapshotted to your files too — your own private copy, immune to link-rot.

against link-rot
$ plainkeep bookmark https://example.com/essay --archive
✓ saved as a note in wiki/bookmarks/
  readable text pulled in · page snapshot archived

# a year later:
$ plainkeep search "that essay about slow software"
1. wiki/bookmarks/example-essay.md
plainkeep backup · share · invoice

Safe copies. Careful sharing.

Backups are encrypted and go off-machine with a key that can only add — so even a compromised laptop can't erase your history. Your code repos get swept into compact bundles on the same rhythm. And when you need to show someone a note, share makes an expiring link — which you send. The system itself never transmits anything, anywhere, ever: even invoices come out as drafts for you to send.

durability, gated
$ plainkeep backup run
✗ backing up needs your explicit yes
  re-run: plainkeep backup run --yes

$ plainkeep backup run --yes
✓ encrypted snapshot uploaded (append-only key)

$ plainkeep share wiki/notes/rrf.md
✓ expiring link created — you decide who gets it
plainkeep new verb · plugin

Missing a command? Make one.

Your own commands live in your vault's plugins/ folder — never inside the engine, so updates can't overwrite them. Scaffold one in a minute, or install a pack someone published. A new command automatically appears in help, in the menus, in tab-completion, and to AI assistants — and the safety rules gate it exactly like a built-in. New commands start on a short leash (ask first class) until you explicitly trust them.

extend it
$ plainkeep new verb standup
✓ scaffolded plugins/local/standup/ (run.py + cmd.json)

$ plainkeep plugin add you/plainkeep-pomodoro --yes
$ plainkeep plugin trust plainkeep-pomodoro --yes
# until trusted, a plugin can't act without asking
plainkeep ui

The guided menu.

One small, self-contained program (no extra installs, checksum-verified) that turns the whole command surface into menus and forms. It generates itself from the machine-readable command list, so a command you added five minutes ago is already in the menu. Point, pick, done — and it shows you the real command it ran, so the menus quietly teach you the typed way.

plainkeep doctor · setup

It tells you what's wrong — and updates can't hurt you.

plainkeep doctor checks everything and answers with next steps, not riddles: what's healthy, what's missing, and the one-line command that fixes each thing. And because the engine is installed outside your vault as a read-only, versioned tree, an update swaps the tool without ever touching a note: the new version is checked and self-tested before it goes live, and the version you were on is always kept, so rolling back is a tested one-liner — never a prayer.

plainkeep setup — the layer dashboard
setup layers:
  ✓ skeleton    Vault structure         ready    required
  ✓ automation  Schedules               ready    optional  6 jobs loaded
  ✓ search      Semantic search         ready    optional
  ! backups     Durability              blocked  optional  restic is required

  • Optional layers — semantic search, local models, backups, schedules, the UI — are switched on one at a time, each previewable with --dry-run.
  • An interrupted update finishes safely on re-run; it can never leave you with nothing.
  • plainkeep status and plainkeep orient answer the daily question: where was I?
