how it works

You say what you want. It does the filing.

plainkeep lives in the terminal — but you don't need to be a terminal person. A command here is a short, readable sentence, and this page shows you everything about how one works: what it's made of, what happens when you press Enter, and why it's hard to get wrong.

A command is a sentence.

Every plainkeep command has the same shape: the tool, the thing you're working with, what to do with it, your own words, and optional switches. Hover or tap each part below.

anatomy of a command
plainkeep
The tool. Every command starts with it — there's exactly one program to know.
task — the verb
The thing you're working with: task, wiki, search, job… Each verb owns one area of your life.
add — the action
What to do with it: add, list, done, move… Simple verbs skip this part entirely.
your words
The content, in quotes, exactly as you'd say it. You never format anything — the command does.
--dry-run — a switch
Optional extras. This one means "show me what would happen, but don't do it" — it works on every command that changes anything.

That's the whole grammar. Every one of the ~30 verbs follows it.

Don't want to type? Pick from a menu.

plainkeep ui opens a guided menu in the terminal: arrow keys, type-to-filter, forms that ask for exactly what a command needs. It isn't a separate app — the menus are generated from the same command list, so every pick becomes a regular command underneath. Learn by watching what it runs; graduate to typing when (and if) you feel like it.

picking — plainkeep ui
◇  task — pick an action
│  ● list   ● add   ● show   ● move   ● done
│
◇  title
│  Fix the Acme webhook
│
✓  plainkeep task add
   id      T-20260816-01
   status  active
typing — the same thing
$ plainkeep task add "Fix the Acme webhook"
✓  plainkeep task add
   id      T-20260816-01
   status  active

# same door, same result — the menu just typed it for you

What happens when you press Enter.

Five things, every time, in the same order — whether the command came from you, a menu, the schedule, or an AI assistant.

1 · It reads you

The command is checked against the grammar above. Mistyped? You get the corrected version to copy, not an error wall.

2 · Safety check

Every command is classified before it runs: a read, a safe write, or something that needs your explicit yes. Some things are always refused.

3 · The work

Files are created, edited, or found — in the right folder, with the right format and links. That knowledge lives in the command, not in your head.

4 · A snapshot

The change is recorded with git. Any edit — even a wrong one — is one git revert from undone.

5 · It reports

You get a short, human answer. Software asking the same thing gets a precise JSON answer instead — same facts, different clothes.

You can't really get it wrong.

Four safety nets mean a wrong command costs you seconds, never data.

a refusal teaches
$ plainkeep backup run
✗ backing up needs your explicit yes
  re-run: plainkeep backup run --yes

# a "no" always carries the exact corrected command.
# nothing happened; nothing was half-done.
preview anything
$ plainkeep archive old-website --dry-run
would: bundle the repo, move it out of ~/work,
       link the bundle from its project note
# --dry-run writes NOTHING — it's a read.
# works on every command that changes things.
0 it worked 2 mistyped — here's the fix 3 needs your yes 4 nothing by that name 5 refused, on purpose

Every command ends in one of five outcomes — numbered, so software can react to them too. That's the whole protocol.

Plus: plainkeep help lists everything with a summary, and tab-completion fills in your actual note names and task IDs — pulled live from your own files.

A day with it.

The daily rhythm is a handful of commands — and the two bookends, start and close, run on a schedule by default, so the day begins and ends even when you forget to.

a day in the vault
07:30 — the schedule already ran `plainkeep start`: today's journal is open,
        yesterday's unfinished tasks carried forward. You just show up.
 
plainkeep capture "RRF beats naive hybrid search"
✓ saved to inbox/ — zero decisions at capture time
 
plainkeep triage
1 of 3 · "RRF beats naive hybrid search"
  proposes: a wiki note in wiki/notes/ — you approve, it files
 
plainkeep search "ranking fusion"
1. wiki/notes/rrf.md#reciprocal-rank-fusion  …combines rankings by…
 
plainkeep open rrf
one resolver: task id → note name → file → falls back to search
 
18:30 — the schedule runs `plainkeep close`: the day's facts digested into
        the journal, loose ends flagged for tomorrow. Whether you typed or not.

The safety rules, spelled out.

Before any command runs — yours, the schedule's, or an AI's — it's classified into one of five classes. The class decides what it's allowed to do without asking you.

ClassIn plain words
readjust looking — runs freely, even unattended
safe_writewrites inside your own folders — every change is a git snapshot you can undo
draft_onlyproduces a draft (an invoice, say) — the system never sends anything, ever
confirmneeds your explicit --yes — without it you get the corrected command, and nothing happens
denyalways refused: deleting recklessly, touching secrets, writing outside the walls

New and unfamiliar commands start at confirm until you promote them. Trust is earned, even by the tool's own parts.

Where things live.

Four folders, separated on purpose. Your vault holds only text, so it stays small and fast; code and heavy files live next to it, never inside it. The safety walls are built along these lines.

the vault

Notes, tasks, journal, plus commands you add. All text.

✅ your own git repo
~/work

Code — each project its own repo, tracked from the vault.

each repo separately
~/files

Heavy files — client docs, PDFs, recordings. Each has a small text "shadow note" in the vault, so search still finds it.

backed up, not in git
~/dotfiles

Machine setup; puts plainkeep on your PATH.

✅ separately

One more wall worth knowing: the app itself is installed outside your vault, read-only and versioned. The tool can never overwrite your notes, and your notes never contain the tool — updates swap the engine, never touch your files.
